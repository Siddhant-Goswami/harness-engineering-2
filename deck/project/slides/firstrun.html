TIME: minute 24 to 35. This is the longest hands-on block. First, open harness/CLAUDE.md and read it aloud. It is 20 lines. It says: write a brief in three parts, cite link ids, answer decisions in one word. It says NOTHING about who the reader is. Do not point that out; let the failure show it. Run the first command. It takes about 15 seconds. Read the brief out loud as if it were for you. Then run the second command to score it. On the sample month the first setup fails in the same visible ways every time. Expect: - It treats urgent news about tools the reader does not use (Anvil, Quill DB) as action items. - It cites a newsletter recap alongside the changelog it restates. - It misses dull titles that hide a breaking change. Have the room write ONE failure each in failures.md, in the shape on the slide: what they saw, what they expected. Give it a tag, F1. Take three examples from the room. If a brief comes back fine: run week 3, which is weaker on the first setup. CLICK at the end: “Which of its steps needed a model at all?” Let them think. Reading 25 pages one by one is not a judgement call. Deciding which matter is. That question is the bridge to the next slide.
